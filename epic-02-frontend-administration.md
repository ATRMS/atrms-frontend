# Epic 02 — Frontend: Administration Module

> **Goal:** Implement all UI screens for the Administration section. Each task here maps
> directly to a backend task in `epic-02-backend-administration.md`. The backend task
> number is referenced in each task header.
>
> **Depends on:** Epic 01 Frontend (scaffolding) fully complete.
> Backend Epic 02 endpoints must be available (at minimum mocked via MSW for development).
>
> **Route prefix:** `/admin/`
> **Layout:** All screens use the authenticated dashboard layout (sidebar + topbar).
> **Permissions:** Every action button/form is gated by `<PermissionGate>` matching
> the corresponding backend permission code.

---

## Shared Screen Pattern

Every administration list screen follows this layout:

```
┌─────────────────────────────────────────────────────────┐
│ Page Header                                              │
│ Title + Description                    [Primary Action] │
├─────────────────────────────────────────────────────────┤
│ Filter Bar                                              │
│ [Search Input]  [Status Filter]  [Other Filters]        │
├─────────────────────────────────────────────────────────┤
│ DataTable                                               │
│ Col1  Col2  Col3  ...                        [Actions ▾]│
│ ...                                                     │
├─────────────────────────────────────────────────────────┤
│ Pagination                         Rows per page: [20▾] │
└─────────────────────────────────────────────────────────┘
```

Create/Edit actions open a **Sheet** (side drawer) or **Dialog** depending on form size:
- Simple forms (≤ 5 fields) → Dialog
- Complex forms (> 5 fields, multi-section) → Sheet (right-side drawer)

## TASK-F201 — Business Lines Screen
*Backend ref: TASK-201*

**Route:** `/admin/business-lines`

**List screen:**
- Columns: Code, Group (badge), Business Line Name, Status (badge), Created Date, Actions
- Filters: Group (dropdown), Status (Active/Inactive toggle)
- Actions per row: Edit, Deactivate (with confirm dialog) — gated by permissions
- "Add Business Line" button → opens Dialog

**Create/Edit Dialog:**
```

  Group        [Select — NON_OIL_PRODUCING | ACADEMICS | ARTISAN | ...]

```
- Code is auto-generated by the backend — not shown in the form, shown in the list

- Click Deactivate → ConfirmDialog: "Deactivate [Name]? This cannot be undone from this screen."

- On success → row status badge updates to INACTIVE (via cache invalidation)

**Permission gates:**
- "Add Business Line" button: `BUSINESS_LINE_CREATE`
- Edit action: `BUSINESS_LINE_UPDATE`
- Deactivate action: `BUSINESS_LINE_DEACTIVATE`

## Shared Frontend Notes for This Epic

### Dropdown Pre-fetching
Reference data (regions, tax offices, roles, tax types) is used across many screens.
Pre-fetch and cache these with TanStack Query at the layout level so individual
screens don't each trigger a separate network request:

```typescript
// src/app/(dashboard)/admin/layout.tsx
// Prefetch common reference data used across all admin screens
queryClient.prefetchQuery({ queryKey: ['regions-ref'], queryFn: ... });
queryClient.prefetchQuery({ queryKey: ['tax-offices-ref'], queryFn: ... });
queryClient.prefetchQuery({ queryKey: ['roles-ref'], queryFn: ... });
queryClient.prefetchQuery({ queryKey: ['tax-types-ref'], queryFn: ... });
```

### Currency Formatting
All monetary amounts displayed as Nigerian Naira:
```typescript
// src/lib/utils.ts
export const formatNaira = (amount: number) =>
  new Intl.NumberFormat('en-NG', { style: 'currency', currency: 'NGN' }).format(amount);
// Output: ₦1,250,000.00
```

### Inactive Records in Dropdowns
When editing a record that references a now-inactive item (e.g. a tax office assigned to a
user but later deactivated), the dropdown must still show the inactive item as the current
selected value with an "(Inactive)" suffix — but not offer it as a new selection.
